# 主跌段放空觀察系統

使用者已確認 2026-11-06 的 v0.1 規格。本系統是獨立收盤研究與追蹤工具，沒有下單功能；技術分數不等於可交易資格，也不保證獲利。

## 原系統隔離

- 原 `index.html`、台／美股掃描器、大盤濾網、部位計算器、策略鎖定與追蹤均保持原檔內容。
- 放空入口在 `short/index.html`；資料只寫入 `data/short/`，來源與計算在 `scripts/short/`。
- 瀏覽器收藏、資金與個人筆記只使用 `shortObservation.v1.*`，不搬移或覆蓋原做多及舊示範站設定。
- `tests/short/legacy_source_hashes.json` 保護原始靜態來源；原台股 frozen fixture 不改動。另增加原美股上升、下降、盤整三組固定輸出回歸。

## 三頁操作

主跌段觀察、放空部位計算機、放空策略追蹤。支援台／美股、手機滑動、桌面頁籤及鍵盤。預設最多五檔優先觀察，備查每次增加十五檔。搜尋／排序使用精簡索引，展開卡片時按版本載入最多十五檔詳細資料。

所有價格指標使用觀察區中間值；缺值或不符合 `stop > entry > target > 0` 時，不產生有效風報比。帶入計算機後即時計算；確認按鈕保存目前確認狀態，後續修改即清除該狀態。幣別分開，不換算資金。

## 策略版本與規則

`scripts/short/config.py` 是確認後參數的唯一來源；目前沒有參數最佳化。

- MA20／MA60、五日斜率、左右各兩日確認的波峰谷，連續兩日建立空頭趨勢。
- 平台使用當日前二十根，寬度不超過12%、兩次相隔三日的支撐測試；收盤跌破0.25 ATR、量比1.5倍。
- 跌破後十日內等待反彈，再由不同後續交易日收盤跌破反彈低點0.1 ATR；轉弱窗口三日。
- 均線反彈先有三日收盤在均線下，再反彈、再轉弱；壓力使用反彈前已知均線。
- 低於跌破價2 ATR、低於MA20達2.5 ATR或五日跌幅12%，禁止追空。
- 跌破後一至三日收盤收復原支撐0.25 ATR，標示疑似假跌破。
- ATR14 Wilder。觀察區為確認收盤上下0.25 ATR。停損依結構，第一目標選擇事前已知的較近支撐／平台量測目標，不移動目標來湊風報比。
- 品質分：趨勢25、結構25、量價15、停損距離15、風報比20。優先技術候選需至少80分、趨勢確認、有效進場型態、風報比至少2及停損距離不超過6%，且沒有跌深／假跌破／公司行動觀察期。
- 大盤分為空方有利、等待、多方強勢、資料不足。只控制交易分級，不刪除原始訊號。

完整必要條件、排除條件、確認與失效時點見 [STRATEGY_SPEC.md](STRATEGY_SPEC.md)。

## 交易資格

台股融券與借券賣出分別保存。官方市場可借券賣出額度不是券商庫存；沒有可靠日期時不以擷取時間冒充資料日期。券商庫存、locate、借券費、完整交易限制與事件資料未接入前，維持「交易資格／券源待確認」。

計算機輸出名目研究股數，成本、單邊滑價、借券年費率、天數與股息補償均納入風險。手動輸入保證金比例只增加假設展示，仍不宣稱實際可下單股數。未模擬券商維持率、追繳與強制回補。

## 收盤資料與異常處理

沿用 Yahoo Finance／yfinance 歷史資料及台股 TWSE／TPEx 官方收盤。台股最新日K在驗證前以官方OHLCV覆蓋。時區及提早收盤使用 exchange_calendars，台股近期交易日再以官方指數月報核對。

檢查日期、重複、NaN、零價格、OHLC範圍、成交量與缺失交易日。部分上櫃歷史資料存在 OHLC 範圍不一致：原始回應保存在忽略版控的 `data/short/cache/raw/`；不修補價格，只採最後一根異常之後的連續有效區段。至少120根有效資料才分析，歷史被隔離的範圍在研究覆蓋報告揭露。

公司行動僅在生效日起調整當時已知歷史，不用今天的調整收盤倒改舊訊號。歷史公告時點不完整仍列限制。API失敗保留最後成功JSON與原始資料日期，另寫狀態／健康報告；前端失敗使用最後成功資料並提示，超過36小時未核對也提示重新確認。

## 追蹤生命週期

原始觀察區、停損、目標、首次訊號日及版本保存雜湊，不可覆蓋。入選後即使隔日不在清單仍保留；十日未觸發到期，已觸發最多二十個交易日。

只在訊號確認後的下一交易日開盤、價格位於原觀察區且事前條件允許時，記錄技術觸發；不把當日最低價倒當成交價。正式追蹤須在預定開盤前建立，時間未知或事後建立不得回填過去成交。未進場不列交易績效。日K按日期判斷低點達標、高點停損，已知開盤跳空優先處理；同日順序不明需人工確認。缺少中間交易日就停止推進，不跳過資料缺口宣稱達標。目標先達成後保持終局。拆股只換算執行層，股息補償是放空負債。

## 歷史研究與限制

訓練期2015–2021、驗證期2022–2023、歷史保留期2024起。保留期前30交易日隔離，按事前日期排除跨界持有；不依輸贏剔除樣本。

報告含觀察數、觸發率、目標達成率／同日未知上下界、平均盈虧比、期望R、最大回撤情境、連續虧損、不同盤勢與幣別組合。保留全部研究事件於 `backtest_trades.json`。研究組合採未槓桿名目曝險、每筆1%風險、單筆20%／總計100%名目曝險、最多五筆、1% ADV，不能視為券商保證金模型。

**技術訊號回測，非可執行放空績效。** 目前使用現行存續名單，缺乏歷史全市場／下市名單、歷史券源、召回、完整歷史限制與事件時間，因此存活者偏誤及可執行性尚未解決。成本是研究假設，不是官方實際費率。不得宣稱已證明高勝率、最佳參數或樣本外可獲利。

## 執行與部署

```sh
python -m pip install -r requirements-short.txt
python -m scripts.short.run_update
python -m scripts.short.index_history
python -m scripts.short.backtest
python -m scripts.short.public_data
python -m unittest discover -s tests/short -p 'test_*.py' -v
npm --prefix short ci --ignore-scripts
npm --prefix short test
python -m scripts.short.check_legacy
```

最後一個命令保留真實失敗狀態。本次檢查時原完整測試有一個既有資料覆蓋失敗（2035、2755）；沒有修掉或改expected來美化結果。

GitHub Pages可直接提供 `/short/`。獨立公開Sites版本使用相同前端與收盤快照；前端優先讀main上的放空資料，無法取得時讀部署快照／本機快取並顯示原日期。主分支尚未有放空資料時，使用部署快照。

新增的 `update-short-data.yml` 合併至main後才會啟用排程，與原資料寫入佇列共用concurrency，但只提交 `data/short/`。日常更新收盤，週日或手動選擇時刷新歷史研究。GitHub排程可能延遲，重新讀取網頁不等於觸發新掃描。
